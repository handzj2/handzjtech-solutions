# CHANGE CONTROL PROCESS

For any material change to an approved contract:
1. Identify the affected contract document.
2. Inspect the existing state (workspace + relevant contract).
3. Make a justified change.
4. Validate (install/typecheck/build/lint as applicable).
5. Record the change in CHANGE_LOG.md.
6. Record significant decisions in DECISIONS.md.

No silent changes. Scope is not expanded without explicit authorization from the project owner.
